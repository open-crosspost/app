Route the X connect flow through the connector's `exchange_code` enclave operation: the API dispatches the OAuth code + PKCE verifier to the OutLayer run (the same server-side bridge the scheduler uses) instead of calling X's token endpoint, reads the minted refresh token from the run answer under `connect.X_REFRESH_TOKEN`, and writes it into the caller's row via ECIES as before. No server holds the OAuth client secret: the app.api drops `X_CLIENT_ID`/`X_CLIENT_SECRET` entirely, the author row (profile `author`, `X_OAUTH_CLIENT_ID`/`X_OAUTH_CLIENT_SECRET`) is provisioned once on the publishing account's wallet with the outlayer CLI (connector repo MAINNET_RUNBOOK §4), and the twitter plugin keeps only the public client id + PKCE for the consent URL. The wallet registration lands before the exchange dispatch. The API also surfaces run-level refusals that arrive inside a completed answer envelope (`success: false`, the sentence under `output.error`). The UI classifies connector refusal prefixes (`credential_busy:`, `rate_limited:`, `credential_expired:`, `policy_denied:`, …) into curated `RATE_LIMITED`/`UNAUTHORIZED`/`PLATFORM_ERROR` error details, keeping the raw sentence in `details.raw`.
